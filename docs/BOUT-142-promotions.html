Appliquer des promotions configurables par le marketing lors de la création d'une commande

Joindre Ajouter une sous-tâche Lier un ticket

Description

En tant que responsable marketing,
je veux pouvoir créer et activer des promotions sans dépendre d'une mise en production,
afin de lancer rapidement des opérations commerciales et augmenter le panier moyen.

Contexte

Aujourd'hui, le total d'une commande est calculé uniquement à partir du prix unitaire des produits au moment de la commande (OrderLine.UnitPrice). Le marketing veut pouvoir lancer des promotions de façon autonome. Le client doit voir, dans le détail de sa commande, quelles remises ont été appliquées et pour quel montant.

Types de promotions à supporter

TypeDescriptionExemple
Remise catégoriePourcentage de réduction sur tous les produits d'une catégorie.-20 % sur la catégorie Books
Lot « X achetés, Y payés »Pour un produit donné, le client achète X articles et n'en paie que Y.3 Men's T-Shirt achetés, 2 payés
Remise panierMontant fixe déduit à partir d'un montant de commande minimum.-50 € dès 500 € d'achat
Code promoPourcentage de réduction sur la commande, déclenché par un code saisi par le client. Utilisable une seule fois par client.BIENVENUE10 : -10 %

Règles de gestion

  1. RG1 : une promotion a un nom, un type, des paramètres propres à son type, une date de début et une date de fin. Elle peut être activée ou désactivée.
  2. RG2 : seules les promotions actives et dont la période de validité couvre la date de la commande sont appliquées.
  3. RG3 : le code promo est facultatif dans la requête de création de commande. Un code inconnu, expiré ou déjà utilisé par le client entraîne le refus de la commande avec un message explicite.
  4. RG4 : les montants sont exprimés en euros et arrondis au centime.
  5. RG5 : la commande conserve le détail des remises appliquées (promotion, montant de la remise). Ce détail ne doit pas changer si la promotion est modifiée ensuite.
  6. RG6 : le marketing gère les promotions via l'API (création, consultation, modification, désactivation). Aucune promotion ne doit être codée en dur.

Critères d'acceptation

CA1 : Remise catégorie
Étant donné la promotion P1 active
Quand un client commande 2 × Clean Code
Alors le total de la commande est de 63,98 € et le détail mentionne la remise « Rentrée littéraire »
CA2 : Lot « X achetés, Y payés »
Étant donné la promotion P2 active
Quand un client commande 3 × Men's T-Shirt
Alors un seul des trois articles est offert et le total est de 59,98 €
CA3 : Remise panier
Étant donné la promotion P3 active
Quand un client passe une commande de 500 € ou plus
Alors une remise de 50 € est appliquée
CA4 : Code promo à usage unique
Étant donné un client ayant déjà passé une commande avec le code BIENVENUE10
Quand il crée une nouvelle commande avec le même code
Alors la commande est refusée avec le message « Ce code promo a déjà été utilisé »
CA5 : Promotion hors période
Étant donné une promotion dont la date de fin est dépassée
Quand un client crée une commande éligible
Alors la promotion n'est pas appliquée
CA6 : Détail des remises
Étant donné une commande sur laquelle des promotions ont été appliquées
Quand on consulte GET /orders/{id}
Alors la réponse contient le sous-total, la liste des remises (nom de la promotion, montant) et le total
CA7 : Gestion par le marketing
Étant donné l'API de gestion des promotions
Quand le marketing crée une nouvelle remise catégorie via POST /promotions
Alors elle s'applique aux commandes suivantes sans redéploiement

Composants impactés

  • EntretienCiteo.Api : entités, AppDbContext et migration EF Core
  • OrderEndpoints : création de commande (code promo facultatif) et GET /orders/{id}
  • Nouveaux endpoints /promotions

Hors périmètre

  • Interface d'administration (le marketing utilisera Swagger dans un premier temps)
  • Frais de port et promotions associées
  • Recalcul des commandes déjà passées

Définition de terminé

  • Les critères d'acceptation sont couverts par des tests automatisés
  • Les exemples de paniers E1 à E8 sont vérifiés
  • La migration EF Core est fournie et s'applique au démarrage
  • Les endpoints sont documentés dans Swagger
Note du PO : les exemples de paniers ont été calculés par le marketing dans un tableur. N'hésitez pas à revenir vers moi en cas de question avant de démarrer.
